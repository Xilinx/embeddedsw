amd_xspi_hyperbus_hyperram_intr_example.c File Reference

Overview

Demonstrates the AXI XSPI driver with HyperRAM in interrupt mode.

This file contains an interrupt-driven example for the AXI XSPI driver operating in AXI-Lite mode with a HyperBus (xSPI Profile 2.0) HyperRAM device. It is vendor-neutral: any HyperBus HyperRAM returning a valid Identification Register 0 is accepted. The example is tested with an Infineon device, and datasheet citations use the Infineon HyperRAM datasheet as a reference. It performs the same flow as the polled example:

  • Initialization of the AXI XSPI controller and interrupt system
  • Power-up verification of HyperRAM
  • Reading HyperRAM Identification Registers (IR0, IR1) and CR0
  • Memory RAM test: a fresh per-run pattern written across a one row region in chunks and read back. It performs write/read/verify with data integrity and address decode checks.

Interrupt usage: transactions use the message-based AmdXspi_InterruptTransfer API. TXN_COMPLETE/TXN_ERROR are routed through the GIC/INTC to AmdXspi_InterruptHandler, which drives the message queue and invokes the status callback (AmdXspi_SetStatusHandler) with XST_SPI_TRANSFER_DONE. The callback only sets flags (no prints) so it does not perturb bus timing.

NOTE: HyperRAM is self-refreshing DRAM, not flash - there is no flash-style erase command and no defined "erased" value. This example does a RAM test instead. It writes a pattern that mixes each word's address into its value and changes every run. One pass then catches a bit stuck at either level, a chunk written to the wrong address, and a write that fails silently.

This example requires a GIC or INTC interrupt controller in the system.
