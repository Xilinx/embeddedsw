amd_xspi_hyperbus_hyperram_polled_example.c File Reference

Overview

Demonstrates the AXI XSPI driver with HyperRAM in polled mode.

This file contains a polled mode example for the AXI XSPI driver operating in AXI-Lite mode. This example focuses on:

  • Initialization of the AXI XSPI controller
  • Power-up verification of HyperRAM
  • Reading HyperRAM Identification Registers (IR0, IR1)
  • Reading HyperRAM Configuration Register 0 (CR0) default value
  • Memory RAM test: a fresh per-run pattern written across a one row region in chunks and read back. It performs write/read/verify with data integrity and address decode checks.

NOTE: HyperRAM is self-refreshing DRAM, not flash - there is no flash-style erase command and no defined "erased" value. This example does a RAM test instead. It writes a pattern that mixes each word's address into its value and changes every run. One pass then catches a bit stuck at either level, a chunk written to the wrong address, and a write that fails silently.

This example is vendor-neutral: it targets the HyperBus (xSPI Profile 2.0) protocol, not a specific silicon vendor. Any HyperBus HyperRAM that returns a valid Identification Register 0 is accepted. It has been tested with an Infineon device; datasheet citations below use the Infineon HyperRAM datasheet as a convenient reference. The field layout is HyperBus-standard (see the AXI XSPI design doc, section 2.6.1).

HyperBus Protocol (xSPI Profile 2.0) - Command/Address (CA), 6 bytes:

  • CA[47]: R/W# (1=Read, 0=Write)
  • CA[46]: Address Space (0=Memory, 1=Register)
  • CA[45]: Burst type (1=Linear, 0=Wrapped)
  • CA[44:16]: Row and upper column address (word addr bits [31:3])
  • CA[15:3]: Reserved (must be 0)
  • CA[2:0]: Lower column address (word addr bits [2:0])

HyperBus conventions (per the HyperBus spec / Infineon datasheet reference):

  • HyperRAM is word (16-bit) addressable; each CA addresses a half-word
  • Data is Big-endian: first byte on bus = word[15:8]
  • CA bytes are sent MSB first
  • Register/memory reads require latency cycles
  • Memory writes use the same initial latency as reads; register writes use zero latency
