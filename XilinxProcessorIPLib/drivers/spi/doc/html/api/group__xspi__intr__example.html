int SpiIntrExample ( XSpi *  SpiInstancePtr,
UINTPTR  BaseAddress 
)

Runs a minimal test on the Spi device and driver as a design example.

The purpose of the function is to illustrate how to use the XSpi component using the interrupt mode.

The function sends data and expects to receive the same data.

Parameters
[in]SpiInstancePtrPointer to the instance of Spi component.
[in]BaseAddressBase address of the device.
Returns
XST_SUCCESS if successful, XST_DEVICE_NOT_FOUND if the SPI configuration is not found, otherwise XST_FAILURE.
Note
- In XSCT/classic flow, the device configuration is looked up by DeviceId.
  • The function contains an infinite loop such that if interrupts are not working it may never return.

References XSpi_Config::BaseAddress, BUFFER_SIZE, XSpi_Config::IntrId, XSpi_Config::IntrParent, ReadBuffer, SpiIntrHandler(), XSpi::SpiMode, Test, TransferInProgress, WriteBuffer, XSP_LOOPBACK_OPTION, XSP_MASTER_OPTION, XSP_STANDARD_MODE, XSpi_CfgInitialize(), XSpi_InterruptHandler(), XSpi_LookupConfig(), XSpi_SelfTest(), XSpi_SetOptions(), XSpi_SetStatusHandler(), XSpi_Start(), and XSpi_Transfer().

void SpiIntrHandler ( void *  CallBackRef,
u32  StatusEvent,
u32  ByteCount 
)

Handles the status events of the SPI driver.

It is called from an interrupt context such that the amount of processing performed should be minimized. It is called when a transfer of SPI data completes or an error occurs.

This handler provides an example of how to handle SPI interrupts and is application specific.

Parameters
[in]CallBackRefUpper layer callback reference passed back when the callback function is invoked.
[in]StatusEventEvent that just occurred.
[in]ByteCountNumber of bytes transferred up until the event occurred.

References Error, and TransferInProgress.
