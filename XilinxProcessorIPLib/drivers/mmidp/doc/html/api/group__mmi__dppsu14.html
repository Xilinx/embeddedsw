u8  Stream 
)

Allocate VC payload for one MST stream on TX, the immediate branch, and the branch that owns the stream's sink port.

Programs the TX MST VC payload table, updates the branch sink VC payload ID table over DPCD (PAYLOAD_ALLOCATE_SET at 1C0h), waits for VC_PAYLOAD_ID_UPDATED in PAYLOAD_TABLE_UPDATE_STATUS (2C0h), triggers the ACT sequence via CCTL0, then waits for ACT_HANDLED in 2C0h. When the stream has a sink set by XMmiDp_MstSetStreamSink(), sends sideband ALLOCATE_PAYLOAD so the branch forwards the VC to that port.

Call XMmiDp_ComputeTimeSlot() first. VCPID is the stream number.

On failure after the TX table is programmed (e.g. sink table or ACT), the caller must call XMmiDp_ClearPayloadVcIdTable() to recover; this function does not roll back the TX table.

Returns

u32 XMmiDp_ClearPayloadVcIdTable ( XMmiDp *  InstancePtr)

Clear TX and immediate sink VC payload ID tables.

TX: zero MST_VCP_TABLE_REG0..REG7 via XMmiDp_WriteMstVcpTableRegs(). Sink: DP 1.4 VcId=0 DPCD allocate (start slot 0, slot count 0x3F). Downstream branches are cleared separately by XMmiDp_SendSbMsgClearPayloadIdTable().

Returns

XMmiDp_TrainingState XMmiDp_TrainingStateChannelEqualization ( XMmiDp *  InstancePtr)

This function runs the channel equalization sequence as part of link training.

The sequence is as follows: 0) Start signaling with the same drive settings used at the end of the clock recovery sequence. 1) Transmit training pattern 2 (or 3) over the main link with symbol scrambling disabled. 2) The channel equalization loop. If channel equalization is unsuccessful after 5 loop iterations, return. 2a) Wait for at least the period of time specified in the RX device's DisplayPort Configuration Data (DPCD) register, TRAINING_AUX_RD_INTERVAL. 2b) Check if all lanes have achieved channel equalization, symbol lock, and interlane alignment. If so, return. 2c) Check if the same voltage swing level has been used 5 consecutive times or if the maximum level has been reached. If so, return. 2d) Adjust the voltage swing, pre-emphasis, and post-cursor levels as requested by the RX device. 2e) Loop back to 2a. For a more detailed description of the channel equalization sequence, see section 3.5.1.2.2 of the DisplayPort 1.4a specification document.
