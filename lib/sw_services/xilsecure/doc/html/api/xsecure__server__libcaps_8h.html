xsecure_server_libcaps.h File Reference

Overview

This server-only header derives the XilSecure library capability bitmap at compile time.

Each build-gated feature contributes one permanently-assigned bit (see XSecure_LibCapBit in xsecure_defs.h) to the aggregate XSECURE_LIB_CAPABILITIES constant, which the Features command reports to the client alongside the library version.

It lives in server/core (shared server code) rather than a per-platform directory so a single derivation is reused across platforms: the gate macros are named consistently, and a feature not compiled into a given platform simply leaves its gate undefined and contributes 0.

Derivation is entirely compile time (a chain of ifdef checks OR'd together), so there is no runtime cost: a feature that is not compiled in simply contributes 0. Bits are append-only - a new capability consumes a new, previously-zero bit and never disturbs existing assignments, so older clients stay compatible.

Feature gating:

  • PLM_SECURE_EXCLUDE is the umbrella switch: when defined, the whole secure crypto set (RSA + ECDSA + AES) is excluded, so all of those bits read 0.
  • Inside it, PLM_RSA_EXCLUDE and PLM_ECDSA_EXCLUDE are the finer per-engine gates. AES has no finer gate, so AES presence == !PLM_SECURE_EXCLUDE.
  • ECC curve support macros: P-192/P-224/P-256/P-521 are BSP configurable (xsecure_config.h for SDT, xparameters.h for the classic flow); P-384 is always supported when ECDSA is in the build.
  • XSECURE_CRYPTOALGINFO_ENABLED is independent of the secure engines.
