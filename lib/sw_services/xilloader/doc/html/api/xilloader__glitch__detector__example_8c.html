xilloader_glitch_detector_example.c File Reference

Overview

This file illustrates Versal Gen2 (2VE-2VM) glitch detector configuration via the Loader IPI command XLOADER_CMD_ID_CONFIG_GLITCH_DETECTOR, and optionally generates an on-chip test glitch via direct MMIO.

To build this application, xilmailbox and xilloader libraries must be included in BSP and xilloader library must be in client mode.

Select which detectors to configure with the CONFIG_* macros below. Each enabled group is packed into one IPI. Defaults: PMC + ASU + LPD (CONFIG_{PMC,ASU,LPD}_GD = 1).

Optional test-glitch stimulus (TEST_GLITCH_*):

  • There is no Loader IPI for test-glitch generate. When TEST_GLITCH_ENABLE is 1, this example programs test mode / test glitch sel / test glitch gen with Xil_Out32 after a successful configure IPI. Per-block TEST_GLITCH_{PMC,ASU,LPD}_GD macros further restrict which detectors are pulsed (and only if that group was also selected for configure).
  • Direct MMIO only works if the running processor's isolation/XPPU-XMPU protection configuration grants it access to pmc_analog, asu_global, and lpd_slcr; the Loader IPI configure path has no such restriction since it runs on the PLM. If those blocks are isolated from this processor in your design, the writes below will fault - leave TEST_GLITCH_ENABLE at 0 (the default) and rely on the IPI configure only, or drive the glitch from a supply that can reach the block instead.
  • When TEST_GLITCH_ENABLE is 1, GenerateSelectedTestGlitches() reads EAM status immediately after each pulse (PMC ERR3 and LPD SLCR ERR2).

Procedure to run the example.

Load the Pdi. Select the target. Download the example elf into the target.

Note
  • The ASU glitch detector is held in reset out of POR (psx_crl.RST_ASU_GD resets to 0x3) and the boot flow does not release it. Configuration via XLoader_ConfigureGlitchDetector() programs the calibration while the block is held in reset and releases it on the way out. Calibration registers read back correctly even while the block is in reset, so readback alone does not prove the detector is alive.
