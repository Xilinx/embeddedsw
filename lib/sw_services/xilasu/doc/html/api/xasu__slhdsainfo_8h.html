xasu_slhdsainfo.h File Reference

Overview

This file contains the SLH-DSA definitions which are common across the client and server.

Supported: FIPS 205 pure SLH-DSA and HashSLH-DSA (pre-hash) for all four "s" parameter sets (SHAKE/SHA2 x 128s/256s). Pre-hash HashId must match the parameter set per FIPS 205 footnote 18 (PH(M) length >= 2n bytes):

  • 128s (n = 16): XASU_SLHDSA_HASHID_SHA256 (32-byte PH(M)).
  • 256s (n = 32): XASU_SLHDSA_HASHID_SHA512 (64-byte PH(M)).

Message mode (PreHashMode in sign/verify parameters):

  • XASU_SLHDSA_MSG_PURE (0): pure SLH-DSA (default when fields are zero).
  • XASU_SLHDSA_MSG_PREHASH (1): HashSLH-DSA; H_msg/PRF_msg absorb 0x01 || ctx_len || ctx || OID || PH(M).

Context length semantics (pure SLH-DSA, PreHashMode == PURE):

  • CtxLen == 0: FIPS empty context (hashes 0x00 || 0x00 before the message).
  • CtxLen 1..255: FIPS context string at CtxAddr. Sign and verify must use the same CtxLen.

Context length semantics (HashSLH-DSA, PreHashMode == PREHASH):

  • CtxLen 0..255 only. Empty context uses 0x01 || 0x00 || OID.
  • MsgAddr/MsgLen must reference a client-computed PH(M) digest (32 or 64 bytes per HashId). Sign and verify must use matching PreHashMode, HashId, and CtxLen.

Sign mode (SignMode in sign parameters):

  • XASU_SLHDSA_SIGN_MODE_HEDGED (0, default): ASUFW draws fresh add_rand (n bytes) from TRNG for each sign (FIPS hedged signing, recommended).
  • XASU_SLHDSA_SIGN_MODE_DETERMINISTIC (1): ASUFW uses PK.seed as add_rand (deterministic).

IPI parameter structures:

  • XAsu_SlhdsaSignParams: sent with XASU_SLHDSA_SIGN_CMD_ID.
  • XAsu_SlhdsaSignVerifyParams: sent with XASU_SLHDSA_SIGN_VERIFY_CMD_ID. All 64-bit address fields must reference DMA-visible shared memory.
