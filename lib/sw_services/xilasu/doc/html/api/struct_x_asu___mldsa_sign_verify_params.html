Detailed Description

This structure contains ML-DSA signature generation/verification parameters.

Both operations share the same layout and are mutually exclusive, so a single generic parameter set is used:

  • For signing, KeyAddr/KeyLen refer to the input secret key and SignatureAddr is the output signature; Deterministic selects the randomness mode.
  • For verification, KeyAddr/KeyLen refer to the input public key and SignatureAddr is the input signature; Deterministic is unused and must be left zero. The key is supplied either directly through KeyAddr/KeyLen or from the ASU key vault through KeyId. Exactly one of the two must be non-zero, as enforced by XAsu_KmValidateKeyAddrNdKeyId. ShaType and ShaMode select the HashML-DSA pre-hash function and are used only when SignMode is XASU_MLDSA_SIGN_MODE_PREHASH; they must be left zero for pure ML-DSA. The pair encodes 7 of the 12 pre-hash functions FIPS 204 approves: SHA2-256, SHA2-384 and SHA2-512 with XASU_SHA2_TYPE, and SHA3-256, SHA3-384, SHA3-512 and SHAKE256 with XASU_SHA3_TYPE. The remaining five, SHA2-224, SHA2-512/224, SHA2-512/256, SHA3-224 and SHAKE128, cannot be requested: the SHA mode encoding defines only XASU_SHA_MODE_256/_384/_512/_SHAKE256, and the ASU SHA hardware offers no programmable initial value for the truncated SHA-2 variants nor a programmable rate for the remaining Keccak ones.
